# Обновления WorldWay через GitHub

Приложение уже умеет проверять GitHub Releases, скачивать APK и открывать системную установку. Для начала работы нужно опубликовать подписанный APK как файл релиза. Простого обновления исходников на GitHub недостаточно.

Используется публичный репозиторий murtmarsel/WorldWay. Актуальные исходники 1.0.6 загружены в master. Обновления приложения берутся из опубликованных GitHub Releases: одного изменения исходников недостаточно.

## Как обновлять исходники дальше

Основная локальная папка WorldWay уже подключена к master этого репозитория; авторизация Git сохранена в стандартном Windows Credential Manager.

В GitHub Desktop выберите File → Add local repository и укажите папку WorldWay. После редактирования проекта просмотрите Changes, укажите описание и нажмите Commit to master, затем Push origin. Не добавляйте ключи подписи, SMTP-настройки или логи. Для следующего выпуска отдельно увеличьте версию, отправьте исходники и создайте Release.

## Самый быстрый запуск: ручной релиз

1. На GitHub откройте репозиторий → Releases → Draft a new release.
2. Создайте тег v1.0.6. Имя релиза укажите точно: `1.0.6 (7)`. Число в скобках — настоящий Android VERSION_CODE из version.properties.
3. Прикрепите файл WorldWay-1.0.6.apk. Архив исходников, который GitHub добавляет сам, приложение установить не сможет.
4. Укажите изменения, опубликуйте обычный релиз (не Draft и не Pre-release).
5. На устройствах с меньшим versionCode и включёнными обновлениями приложение получит новую версию при следующем открытии главного экрана.

Релиз 1.0.6 не будет предлагаться уже установленной 1.0.6. Следующий выпуск: VERSION_NAME=1.0.7, VERSION_CODE=8, тег v1.0.7, имя 1.0.7 (8).

Для обновления без потери данных всегда используйте тот же ключ подписи, что у установленной версии. Текущий SHA-256 сертификата:
a8e2b489cfebcc2b613f07ea221b0c22e0773a18b52b4f352cdde3b31f3f6e0e.

Android требует разрешить установку из этого приложения и подтвердить установку системным диалогом. Обычное приложение не может незаметно заменить себя без подтверждения. Проверка и загрузка могут выполняться автоматически.

## Автоматическая сборка и публикация

Подготовлен .github/workflows/android-release.yml. Он уже загружен на GitHub; автоматическая сборка пока не запускалась.

Исходники уже перенесены в репозиторий. Для автоматических следующих выпусков остаётся настроить GitHub Secrets и запускать workflow после изменения версии и RELEASE_NOTES.md.

Не переносите приватные ключи, server-audit/private/, local.properties, архивы проекта, логи, .gradle/ и build/. Исключения добавлены в .gitignore. Сам .gitignore не удаляет секреты, если они уже были закоммичены ранее.

В репозитории Settings → Secrets and variables → Actions добавьте:
- WORLDWAY_KEYSTORE_BASE64 — содержимое существующего keystore в Base64;
- WORLDWAY_STORE_PASSWORD — пароль хранилища;
- WORLDWAY_KEY_ALIAS — alias ключа;
- WORLDWAY_KEY_PASSWORD — пароль ключа.

Используйте сохранённый прежний ключ. Не генерируйте новый debug.keystore в GitHub runner: его подпись не совпадёт с уже установленным приложением. Keystore и пароли не должны находиться в исходниках или в переписке.

Перед выпуском обновите version.properties и RELEASE_NOTES.md, отправьте изменения. Затем Actions → Build and publish Android release → Run workflow. Сценарий соберёт и проверит приложение, сверит подпись с существующим сертификатом и опубликует релиз с правильным именем. Временный файл ключа удаляется после выполнения.

Выпуск с уже существующим тегом не перезаписывается. Увеличивайте VERSION_CODE для каждой новой сборки. Автоматическое увеличение версии во время assembleRelease убрано, чтобы номер внутри APK не расходился с номером опубликованного релиза.

## Исправления клиента обновлений

- versionCode берётся из имени релиза и сверяется с загруженным APK; вычисление из X.Y.Z исключено.
- Принимаются HTTPS-ссылки на APK в указанном GitHub-репозитории.
- Путь Download/updates разрешён для FileProvider.
- Перед установкой сверяются packageName, версия и сертификат подписи.
- Загрузка имеет ограничение времени и поддерживает отмену; Thread.sleep заменён на coroutine delay.

Документация Android об установке: https://developer.android.com/reference/android/content/pm/PackageInstaller
